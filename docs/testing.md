# mitool 测试说明

> 适用版本：mitool v1.3（C# / .NET 10，单文件 `mitool.exe`，约 159 KiB / 163 KB）
> 可执行文件位置（按构建方式）：
> `src/mitool/bin/Release/net10.0-windows/mitool.exe`

---

## 0. 测试前准备

| 项 | 说明 |
|---|---|
| **必须用管理员终端** | 访问 `root\wmi` 下的厂商类需要管理员权限；非管理员一律 `拒绝访问`。`mitool.exe` 已带 `requireAdministrator` 清单，双击会自动弹 UAC，但在 PowerShell 里跑最方便 |
| 打开方式 | `Win+X` → 「终端(管理员)」 / 「Windows PowerShell(管理员)」 |
| 先切换目录 | 下面所有命令都假设已执行过 `cd`（每段都自带，整段粘贴即可） |

**测试前请知悉**：mitool **不会**碰 Windows 电源模式、电源计划、睡眠/休眠设置，也不会改厂商软件的注册表配置。它只做一件事——通过 `root\wmi : MICommonInterface.MiInterface` 往固件收发命令。

---

## 1. 第一步：只读自检（安全，建议先跑）

**这一段全是只读操作，不改任何状态。**

```powershell
cd src\mitool\bin\Release\net10.0-windows
.\mitool.exe probe
.\mitool.exe status
.\mitool.exe mode get
.\mitool.exe charge get
```

### 预期输出与判读

**① `probe`**

```
通道：可用
档位：均衡
```

| 判读点 | 通过标准 |
|---|---|
| 通道 | 显示「可用」 |

**② `status`**

```
档位：均衡
供电：插电
电量：100%
Windows 视角充电中：否
```

**③ `mode get`**

```
档位：均衡
```
> 静谧 / 省电等 mitool 不暴露的档位也会照实显示（"静谧" / "省电"），但不会被擅自改回。

**④ `charge get`**

```
充电状态：固件层读不可用
供电：插电
电量：100%
Windows 视角充电中：否
```
> 固件层的充电读命令**只回显**，mitool 拿不到当前是否在保护的状态。Windows 视角的"充电中"是另一回事（电池驱动报告）。

## 2. 功能测试项

### T1 切到高性能档（写 + 自动回读）

```powershell
cd src\mitool\bin\Release\net8.0-windows
.\mitool.exe mode set performance
# 或用 mode 子级短别名（任选其一）：
.\mitool.exe mode p
.\mitool.exe mode perf
```

**预期：**

```
已切换到：高性能
```

| 通过标准 | 说明 |
|---|---|
| **「已切换到：高性能」** | 写入成功 + 固件回读确认一致 |

**旁证（可选）**：风扇声变大、机身/键盘区变热（这是"高性能"的正常代价）。

### T2 切回均衡档

```powershell
.\mitool.exe mode set balanced
# 或：.\mitool.exe mode b
```
**预期**：`已切换到：均衡`

### T3 恢复默认

```powershell
.\mitool.exe reset
```
**预期**：`已恢复到：均衡`

### T4 开启充电保护（固定 80%）

```powershell
.\mitool.exe charge on
```

**预期：**

```
已开启充电保护（80%）
```

> v1.3 起 `charge on/off` 已**无需** `--yes` —— 命令本身即代表用户意图，按 Enter 即生效。

**载荷对照**：`00 FB 00 10 02 00 01 00…` 里 `01` 是 **80% 的档位码**（不是百分比）→ 写在 `InData[6]`。

> ⚠️ **修订说明（重要）**：固件的充电参数是**档位码**（合法集 `{0,1,4,5,6,7,8}`），不是百分比：
> `1 = 80%（推荐）`、`0 = 关`、`4/5/6/7/8 = 其它档位`。
> 早期版本误把百分比（80/100）当成档位码下发，被固件当作非法值丢弃 —— 这正是「上限没生效」的根因，本版本已修正为固定 80%（码 1）。

### T5 关闭充电保护

```powershell
.\mitool.exe charge off
```

**预期**：`已关闭充电保护`

> 说明：`0` 就是厂商语义里的"关闭"，且属于合法集，是表达"关"的正确值。

### T6（可选）重启后是否保持

重启电脑后执行 `.\mitool.exe mode get`，看档位是否还是你设置的值。

> 厂商官方说明是「重启回到默认档」。固件对我们直接写入的值是否持久，**尚未验证** —— 这一项就是用来确认它的。

## 3. 充电是否真的生效 —— 必须做这一步

因为**读通道不可用**，充电只能靠**实际充电行为**验证。先做一步准备，再做二选一的验证。

### 准备：先关掉厂商软件的干扰

打开**小米电脑管家 → 电池/充电 页面 → 把「充电保护」关闭**。

> 原因：厂商软件会按注册表 `…\PerformanceMode\POWER\ChargingProtect` 判断是否下发；它处于开启状态时，会在自己的触发点（启动/唤醒/插拔电）**重新下发并覆盖**我们的设置。关掉它，我们的写入才能独立观察。

### 验证 A（快，几分钟）

适用：当前电量高于你要设的值。

1. 确认当前电量（`.\mitool.exe status` 里看「电量」）
2. 执行 `.\mitool.exe charge on`（把上限设为 80%）
3. 观察几分钟：**若电量已超过 80% 且充电被拒绝/停止**（`status` 里「充电中 = 否」，或管家显示"未充电"）⇒ **写入生效** ✅
   （电量本来就低于 80% 时看不出变化，属正常——它只会在充到 80% 时停下）
4. 测完务必 `.\mitool.exe charge off` 恢复

### 验证 B（慢，但最确定）

1. 电量放到 80% 以下（例如 70 左右）
2. `.\mitool.exe charge on`
3. 插电充电，**看是否停在 80%** 而不再往上涨
4. ⇒ **写入生效** ✅；若一路充到 100% ⇒ 未生效

> 补充判据：真阈值是**固件级**的 —— 关机状态下插电也照样停在 80%。如果只在开机时有效，说明它只是软件行为。

## 6. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `拒绝访问：...需要管理员权限` 或 `WMI 0x80041003` | 终端不是管理员 | 用管理员终端重开（`Win+X` → 终端(管理员)） |
| `未找到 MICommonInterface 实例` | 该机型固件未暴露 MIFS 接口 | 档位/充电功能在本机不可用；不要继续写 |
| `WMI 0x8004100f 无效的对象` | 请求非法（参数/载荷不对） | 本机正常使用不应出现；若出现请记录完整输出 |
| `回读确认：... ✗ 未生效` | 写入被拒，或被厂商软件覆盖 | 检查是否装了小米管家；先关其「充电保护」再重试 |
| 提示 `确认后请加 --yes 重试` | 写操作防误触 | v1.3 起已取消该确认；直接执行命令即可 |
| `charge get` 返回与请求相同 | **正常**，本机固件充电读仅回显 | 无需处理，用第 3 节的行为验证代替 |
| 风扇突然变响 / 机身变热 | 切到了「高性能」 | 正常现象；`.\mitool.exe reset` 可切回均衡 |

## 7. 已知限制（如实标注）

1. **充电读不可用** —— 本机固件只实现了充电「写」，读命令仅回显。因此 `charge on/off` 后**无法回读校验**，只能用实际充电行为验证。
2. **充电保护档位固定为 80%** —— 固件的充电参数是档位码（合法集 `{0,1,4,5,6,7,8}`），不是百分比；`1 = 80%（推荐）`、`0 = 关`。其余档位（40/50/60/70%）固件支持但本工具不暴露（按需求固定为 80%）。早期版本误把百分比当档位码下发而被丢弃，已修正。
3. **档位只有两档** —— `balanced`（均衡）/ `performance`（高性能）。固件的另外两档（静谧、省电）不暴露；被 FN+K 或厂商软件切过去时，`mode get` 会如实报出并标注。
4. **与厂商软件共存** —— 厂商软件会在它的触发点（启动/唤醒/插拔电）重新下发自己的配置，可能覆盖 mitool 的设置。测试充电时建议先关掉它的「充电保护」。
5. **需管理员权限** —— 厂商 ACPI-WMI 类对非管理员直接拒绝访问，**连读取也要提权**，这是微软/固件的 ACL 决定，绕不过去。
